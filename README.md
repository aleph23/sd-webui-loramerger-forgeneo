# 4. Added & Refactored Features 

## 4.1. Comparison of our custom SVD merge implementation with kohya_ss and the rationale behind selection 

This extension does not directly call Kohya's official LoRA merge scripts (`kohya-ss/sd-scripts`) in such as `svd_merge_lora.py`, `pluslora.py` as subprocesses or external libraries, instead choosing to include Kohya's code directly.

###  4.1.1. Why implement custom functionality instead of importing kohya_ss? 

- 1. **For full support of LoRA Block Weighting (LBW)**:
  - **Kohya Official**: Only a uniform ratio (scalar value) can be applied to the entire LoRA model. 
  - **Our Unique Implementation**: It ful;ly supports the layered block weighting widely used in WebUI (26 blocks in SD1.5/2.X, SDXL, Flux, and other block structures) and the 'Same to Strength' option. It is necessary to determine the block to which each module belongs (`IN01`, `MID`,  etc.) from the key name, and then perform synthesis and SVD decomposition by dynamically applying different ratios on a module-by-module basis, which cannot be achieved by directly when calling the external scripts. 
- 2. **Optimization of VRAM consumption**: (Chunk Splitting)
  - **Kohya Official**: As a general rule, the design is to load and compute all modules into memory at once, which means that when synthesizing large-scale LoRA models such as SDXL and Flux, there is a risk of rapid depletion of GPU VRAM or host RAM, leading to an OOM condition.
  - **This Unique Implementation**: By batching modules into units of `CHUNK_SIZE = 50` and calling `gc.collect()` and `torch.cuda.empty_cache()` for each chunk, it is possible to safely complete the process without a VRAM overrun, even on consumer-grade GPUs, provided they have at least 12~16GB.
- 3. **Direct integration into WebUI/Gradio environment**: 
  - **Kohya Official**: Designed to run in the CLI (command line interface), making it difficult to seamlessly integrate with memory management within the WebUI (Forge's model unloading), Gradio's progress bar, and exception handling. 
  - **This Unique Implementation**: Tensors are handled directly within the WebUI process. It works closely with Gradio's message notifications and console progress display via tqdm. 
- 4. **Optimizing calculation speed**: (GEMM shortcut for Conv2d 1x1)
  - For convolutional layers with a kernel size of $1\times1$, an optimization path has been introduced that bypasses the heavy 4D convolutional function `torch.nn.functional.conv2d` and `into 2D`, instead `squeezes` the layer, performs batch matrix multiplication (GEMM), and then `unsqueezes` it to restore it, significantly increasing processing speed. 
- 5. **Robust Dimensional Limit Guard**:
  - If the specified rank exceeds the module's input or output dimension (`IndexError`), prevent crashes with `module_new_rank = min(new_rank, in_dim, out_dim)`. A built-in safety mechanism that dynamically clips to the input's upper and lower dimensions. 

### 4.1.2. Algorithm Comparison and Equivalence Verification with the Official kohya_ss Implementation 

This extension's custom implementation has been mathematically and numerically verified to maintain 100% of the calculation accuracy of the official Kohya algorithm. 

| Processing Steps | kohyas/svd_merge_lora.py (Official) | pluslora.py (Custom Implementation) | Judgment |
| :--- | :--- | :--- | :---: |
| **Scaling** | `scale = alpha / network_dim` | `scale = alpha / network_dim` | **Exact Match** |
| **Linear Difference Composition** | `diff = up @ down` | `diff = up @ down` | **Completely Consistent** |
| **Conv2d 1x1 composition** | `(up.squeeze() @ down.squeeze()).unsqueeze()` | `(up.squeeze() @ down.squeeze()).unsqueeze()` | **Exact match** (Optimized) |
| **Conv2d 3x3 Compositing** | `conv2d(down.permute(), up).permute()` | `conv2d(down.permute(), up).permute()` | **Completely Identical** |
| **Singular Value Decomposition** | `torch.linalg.svd(mat)` | `torch.linalg.svd(mat)` | **Completely identical** | 
| **Singular Value Application** | `U = U[:, :rank] @ diag(S[:rank])` | `U = U[:, :rank] @ diag(S[:rank])` | **Exact Match** | 
| **Clamping** | `quantile(dist, 0.99)` Outlier clipping | `quantile(dist, 0.99)` Outlier clipping | **Exact Match** | 
| **Rank cap protection** | `min(new_rank, in_dim, out_dim)` | `min(new_rank, in_dim, out_dim)` | **Exact match** | 
| **Linear Reconfiguration** | `up = U` , `down = Vh` | `up = U` , `down = Vh` | **Exact match** |
| **Conv2d Reconfiguration** | `up.reshape()` , `down.reshape()`| `up.unsqueeze()` , `down.view()` | **Exact match** |
| **alpha setting** | `torch.tensor(module_new_rank)` | `torch.tensor(float(module_new_rank))` | **exact match** |

- **Numerical Verification Results**: When both algorithms were run with the same LoRA weights (Linear, Conv 1x1, Conv 3x3) as input, the maximum difference between the output tensors was observed to be `0.00e+00` (exact bit match), indicating no mathematical difference in the calculation logic.

##  4.2. Early execution of output file duplicate check (Fail-Fast) 

- **Previous Implementation**: Because the system checked for duplicate files immediately before *writing them to a file* (approximately several tens of seconds to potentially several minutes) after all LoRA loading, heavy SVD calculations, and matrix multiplication calculations were completed, computational resources were wasted if overwriting was not enabled. 
- **Present Modification**: Immediately after parameter analysis, just **before** starting GPU computation, the script now checks for the existence of the output file path and if `not "overwrite"`, immediately returns with error.
   
```python 
# Check for duplicate output files before performing merge calculations (especially heavy SVD processing). 
if os.path.isfile(filename) and not "overwrite" in settings: 
    _err_msg = f"Output file ({filename}) exists, enable overwriting or change filename"
    print(_err_msg)
    return _err_msg 
```
